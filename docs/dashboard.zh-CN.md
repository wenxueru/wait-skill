# Wait 看板

## 打开当前会话

使用 Python 3.11 或更新版本，传入当前对话的会话 ID：

```sh
python /path/to/wait/src/waitctl.py dashboard --session "$AGENT_SESSION_ID"
```

- Wait/Loop/Goal 命令也会返回定位所属会话、任务与节点的 `dashboard_url`。复用页面，汇报进度、结果或处理完回调后附上链接。
- 已设置 `CODEX_THREAD_ID` 时，`dashboard` 默认使用该值；否则显式传会话 ID。裸地址不显示任务；仅在需要本机总览时使用 `--all-sessions`。
- 用 `dashboard --state /绝对路径/goal.json` 登记已有 DAG；未选定会话时从状态读取归属，不根据最新任务或浏览器标签猜测。
- 保留返回的完整 URL。添加 `&view=graph` 可直接打开依赖图。

页面默认英文、浅色主题，可在「设置」中切换语言与外观。浏览器按当前地址（含端口）保存选择；新端口使用默认设置。

## 查看进度

会话首页汇总目标与独立等待、循环，状态和进度来自已保存的任务，结束的任务折叠到历史。Goal/Loop 所属 watcher 随父任务展示，Goal 健康检查循环也可从 Loop 查看。

| 视图 | 展示内容 |
| --- | --- |
| 任务列表 | 按标题或 ID 搜索、按状态筛选或点击状态计数；失败、执行中、可推进的任务优先 |
| 依赖图 | Dagre 自动减少交叉、安排跨层连线路径，支持缩放和适应窗口 |
| 任务详情 | 完整标题、依赖、验收条件、已有时间记录、等待和结果 |
| Wait | 查询状态、截止时间、投递、完整说明与结果 |
| Loop | 当前轮次、间隔、下次执行、截止时间与执行历史 |

- 选择任务或依赖链接查看详情；页面会自动选中当前任务。展开标题下方的目标说明可阅读完整内容。
- **最近更新**取自节点事件和生命周期记录，按浏览器本地时区显示，悬停可看完整时间。详情展示已有的创建、开始、等待和结束时间；缺少记录时显示 `—`。
- 搜索与筛选保留依赖图结构，淡化其他节点。布局和展示状态由浏览器计算，资源随 skill 安装，不依赖 CDN。

## 操作任务

| 操作 | 效果 |
| --- | --- |
| 添加节点 | 保存标题、类型、依赖、验收条件与读写范围 |
| 编辑待处理节点 | 修改标题、依赖和验收条件 |
| 重试失败节点 | 恢复为待处理；Agent 仍需确认外部操作是否获准重试 |
| 暂停／恢复 Goal | 停止／允许新派发 |
| 取消 Goal | 将未完成节点标为取消，保留已完成结果 |
| 取消 Wait／Loop | 停止等待程序／阻止后续循环轮次 |

Goal 的暂停和取消不终止已运行的 Agent 或外部作业。页面操作修改保存状态；需要 Agent 立即行动时，在对话中发消息。

## Agent 与页面如何协作

- 照常使用 Wait/Loop/Goal 命令，waitd 自动生成页面；Agent 不编写 HTML、不维护页面摘要、不做额外确认。
- CLI 和页面共用任务状态与命令队列。派发前重读状态，尊重用户编辑、暂停和取消。
- SSE 推送变化，不由模型轮询，也不启动新轮次。
- 状态接口、SSE 和操作接口使用 URL 中的会话范围。一个系统用户共用默认 waitd；会话范围是筛选，不是身份认证。独立状态文件隔离任务，共用文件即共同控制。
- Goal/Loop 命令按模式串行，watcher 并发执行，事件投递到所属会话。

需要手动接续时，使用 `start -- --session ID --no-notify ...` 或 `loop -- init --session ID --no-notify ...`，保留会话归属并关闭自动唤醒。通过 `waitctl follow ID --timeout SECONDS` 阻塞等待，再按模式正常处理事件，包括 Loop 的 `begin`/`complete`。

## 应用预览与远程访问

服务绑定 `127.0.0.1`，应用预览或 SSH 转发可能将它映射到其他回环主机名和端口。保留所有原查询参数，包括 session、mode、focus、node 和 view。

已知映射地址时：

```sh
python /path/to/wait/src/waitctl.py dashboard --session "$AGENT_SESSION_ID" --base-url http://localhost:63671
```

`--base-url` 只修改输出的 URL，保留查询参数，不建立转发或修改 waitd 配置。

SSH 两端端口可以不同。以下将本机 63671 端口转发到远程看板的 35857 端口：

```sh
ssh -N -L 127.0.0.1:63671:127.0.0.1:35857 HOST
```

随后打开 `http://localhost:63671/` 并附上原查询参数，或使用上面的 `--base-url` 生成完整链接。

- 使用 HTTP，主机名为 `localhost`、`127.0.0.1` 或 `[::1]`；显式端口范围为 1–65535。
- 请求带 `Origin` 时，协议、主机名和实际端口必须与请求 URL 一致。
- 看板没有多用户身份验证，转发监听地址应保持为回环地址。

## 更新运行中的安装

修复预览访问时保持活动 waitd 运行。版本不匹配不会停止现有服务：先使用与它匹配的安装，等活动 watcher 结束后，按[服务生命周期](waitd.zh-CN.md#服务生命周期)切换版本。
